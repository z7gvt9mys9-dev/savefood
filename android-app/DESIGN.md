# SaveFood Android — Design Spec

Нативное Android-приложение (Kotlin + Jetpack Compose, Material 3). Документ
фиксирует визуальный язык и информационную архитектуру **до** реализации
экранов. Цель — современный, дружелюбный, content-dense UI для логистики
спасения еды. Это новый дизайн, а не порт верстки веба.

## 1. Принципы

- **Mobile-first, один тап до главного действия** каждой роли.
- **Нижняя навигация (NavigationBar)** вместо длинных скролл-дашбордов.
- **Material You**: динамические цвета на Android 12+, брендовый fallback.
- **Доступность**: контраст AA, тап-таргеты ≥48dp, поддержка крупного шрифта,
  TalkBack-метки, edge-to-edge с корректными insets.
- **Консистентные состояния**: `ShimmerListItem` (загрузка) → контент →
  `EmptyState` с CTA → inline-ошибка с retry.

## 2. Палитра (`core/designsystem/theme/Color.kt`)

| Роль | Light | Dark |
|---|---|---|
| Primary (rescue green) | `#1B9C5A` | `#7DDBA3` |
| Secondary (amber — срочность/истечение) | `#B8690C` | `#FFB871` |
| Error | `#BA1A1A` | `#FFB4AB` |
| Background / Surface | `#FBFDF8` | `#191C1A` |

**Семантические статусы** (`StatusColors`, через `LocalStatusColors`):
`pending` (ожидание) · `active` (в работе) · `done` (готово) · `danger`
(ошибка/просрочка) · `neutral`. Используются в `StatusBadge`.

## 3. Типографика (`Type.kt`)

System sans-serif. Ключевые роли: `headlineMedium` (24/Bold) — заголовки
экранов; `titleLarge` (20/SemiBold) — секции; `titleMedium` (16/SemiBold) —
карточки; `bodyLarge/Medium` — контент; `labelMedium` (12/Medium) — бейджи.

## 4. Формы (`Shape.kt`)

small 10dp · medium 16dp (карточки) · large 24dp (bottom-sheet, диалоги).

## 5. Библиотека компонентов (`core/designsystem/component/`)

- `SaveFoodButton` / `SaveFoodOutlinedButton` — primary/secondary, со спиннером.
- `SaveFoodCard` + `SectionHeader` — базовая карточка и заголовок секции.
- `LotCard` — карточка лота (фото, название, категория/кол-во, срок, адрес,
  статус-бейдж).
- `StatusBadge` (+ `BadgeTone`) — семантические статусы.
- `EmptyState` — иконка + заголовок + описание + CTA.
- `ShimmerBox` / `ShimmerListItem` — скелетная загрузка.

## 6. Навигация и роли

После логина граф ветвится по `role` из JWT (shop / volunteer / needy).
**Админ — только веб**, в приложении его нет. Каждая роль — `NavigationBar`
с 3–4 вкладками.

### 6.1 Нуждающийся — фокус на трекинге заказа

Пассивная сторона: оформляет заявку и **отслеживает уже взятый курьером заказ**.

| Вкладка | Содержание |
|---|---|
| **Мои заявки** (старт) | Трекинг: `ожидает курьера → курьер взял → в пути → доставлено`, карточка/ETA назначенного волонтёра, его позиция на карте, оценка после доставки |
| **Найти еду** | Карта/список активных лотов (таб-переключатель), оформление заявки (wizard) |
| **История** | Прошлые получения, повторная оценка |
| **Профиль** | Анкета, гео-push, экспорт/удаление аккаунта (GDPR) |

### 6.2 Волонтёр — инициатор («ловит» заявку)

Активная сторона: **перехватывает открытую заявку и стартует маршрут**.
Весь главный путь строится вокруг перехвата и доставки.

| Вкладка | Содержание |
|---|---|
| **Доступные** (старт) | Карта/список открытых заявок и лотов; CTA **«Взять заявку» → старт маршрута** |
| **Мой маршрут** | Активный маршрут: точки забора в магазине → доставка, GPS-трекинг, QR/фото-подтверждение, завершение |
| **Рейтинг** | Уровни, лидерборд, благодарности, команда (create/join/leave) |
| **Профиль** | Данные, KYC-документ, история, уведомления |

### 6.3 Магазин

| Вкладка | Содержание |
|---|---|
| **Лоты** (старт) | Активные лоты, редактирование/удаление, подтверждение передачи (QR) |
| **Создать** (FAB) | Wizard создания лота: данные → фото (камера/галерея) → срок/время |
| **Чеки/ESG** | OCR-чеки, ESG-сводка (`/esg`, CSV). **Прогноз списаний исключён.** |
| **Профиль** | Данные магазина, тариф (`/plan`), уведомления, self-pickup |

## 7. Флоу-доминанты (резюме)

```
Магазин:     создать лот ──▶ лот опубликован ──▶ подтвердить передачу (QR)
Волонтёр:    взять заявку ──▶ старт маршрута ──▶ забор ──▶ доставка ──▶ QR/фото
Нуждающийся: оформить заявку ──▶ ТРЕКИНГ (ожидание/в пути) ──▶ получено ──▶ оценка
```

## 8. Карты, камера, QR

- **Yandex MapKit** — карта лотов/заявок (нуждающийся «Найти еду», волонтёр
  «Доступные»), позиция волонтёра при трекинге.
- **CameraX** — фото лота (магазин), фото доставки и удостоверение волонтёра.
- **ZXing** — генерация QR (магазин: подтверждение передачи) и полноэкранный
  сканер (волонтёр: подтверждение доставки).

## 9. Онбординг

Первый запуск — карусель (3–4 слайда по роли) + чеклист первых шагов
(порт идеи `OnboardingChecklist` из веба).
